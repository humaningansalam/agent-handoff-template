# v0.13 rollout

This procedure upgrades one adopted workspace. It does not claim that any other adopter is upgraded or that historical Tasks are rewritten.

## Install and postflight

```bash
SOURCE=/absolute/path/to/agent-workspace-control-plane-0.13.0
./scripts/repoctl upgrade plan --source "$SOURCE" --output .repoctl-state/upgrade-v0.13.0.json --json
./scripts/repoctl upgrade apply --source "$SOURCE" --plan .repoctl-state/upgrade-v0.13.0.json --json
./scripts/repoctl upgrade postflight --json
```

Adopter product code, `docs/PRD.md`, live/archived Tasks, Knowledge records, and repository contents remain preserve paths.

## Task audit and bounded cleanup

```bash
./scripts/repoctl task audit --include-archived --json > .repoctl-state/task-audit-v0.13.0.json
./scripts/repoctl task migrate-slop --include-archived --json > .repoctl-state/task-slop-plan-v0.13.0.json
./scripts/repoctl task migrate-slop --apply --json
```

The apply command rewrites only recognized repoctl-generated cancel arrays and Chosen replacement lists in live Tasks. Archived Tasks are reported but not rewritten because changing them without updating immutable receipts/catalogues would corrupt evidence. Do not present this cleanup as new verification or completion proof.

## Common-guidance cleanup

Older copies may contain model, provider, role hierarchy, or external queue instructions in common files. Upgrade intentionally does not overwrite adopter-authored common guidance. Review these diffs from the extracted release source:

```bash
for file in AGENTS.md docs/workflows/INDEX.md docs/workflows/README.md; do
  git diff --no-index -- "$file" "$SOURCE/$file" || true
done
```

After confirming that a file contains only the old shared template and no adopter-specific policy, replace that file explicitly and review the Git diff:

```bash
cp "$SOURCE/AGENTS.md" AGENTS.md
cp "$SOURCE/docs/workflows/INDEX.md" docs/workflows/INDEX.md
cp "$SOURCE/docs/workflows/README.md" docs/workflows/README.md
git diff -- AGENTS.md docs/workflows/INDEX.md docs/workflows/README.md
```

Do not apply keyword deletion across adopter product documents; model/provider terms may be part of the adopter's own domain.

## Derived maintenance

```bash
./scripts/repoctl knowledge rebuild --repo-id <repo-id> --json
./scripts/repoctl graph build --repo-id <repo-id> --json
```

Knowledge query can fall back to direct v2 records before rebuild. Graph relation queries can use a valid snapshot when provider artifacts or the evidence index are unavailable, but affected capabilities report degraded/partial status and a refresh remains recommended.

## Work-path benchmark per selected product repository

```bash
./scripts/repoctl graph workflow --repo-id <repo-id> --symbol <exact-symbol> --json
./scripts/repoctl graph workflow-benchmark --repo-id <repo-id> --case-id <applicable-case-id> --json
```

The benchmark fixture contains `basic-ml-predict`, `kinport-audio-clock`, `gakza-dart-precision`, and `cops-and-robbers-stale-empty`. Run each only in its matching adopter, never as a cross-repository global mutation. A stale snapshot can reveal current source candidates but cannot prove complete or zero-impact relationships. Evaluate `confirmed_path_recall` separately from candidate-inclusive `path_recall` and refresh Graph explicitly in a rollout-owned change when appropriate.
