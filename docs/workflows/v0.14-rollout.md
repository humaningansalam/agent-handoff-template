# v0.14.0 one-time adopter transition (Rollout Main)

This is a **procedure for one deliberately selected adopter** after its owner's review. It has not been run against the 30 consumers. Do not apply to unrelated repositories, do not run on TabletAuto, and do not copy this control-plane template's PRD into an adopter-owned product. Review existing dirty files, Task status and product documentation before edits.

## 1. Verify a pinned source and protect adopter state

Use the published **v0.14.0** archive `agent-workspace-control-plane-0.14.0.tar.gz`; check its SHA-256 against its release page before extraction. Extract to a separate directory, not over the current workspace. Save a deliberate Git commit/backup for adopter-owned root documents and Task/Knowledge records, including ignored `.repoctl-state` receipts and manifests. Preserve original product repositories, dirty baselines and completion history.

```bash
SOURCE=/absolute/path/to/agent-workspace-control-plane-0.14.0
./scripts/repoctl repo list --json
./scripts/repoctl task audit --include-archived --json
./scripts/repoctl upgrade plan --from "$SOURCE" --output .repoctl-state/upgrade-v0.14.0-plan.json --json
# Review the plan's replace/create/remove operations; do not apply blindly.
./scripts/repoctl upgrade apply --plan-file .repoctl-state/upgrade-v0.14.0-plan.json --json
./scripts/repoctl upgrade postflight --json
```

If postflight finds an archived/closed-task receipt conflict, halt rather than rewriting the receipt to today's hash.

## 2. Explicitly clean known Task-generated slop

```bash
./scripts/repoctl task migrate-slop --include-archived --json
./scripts/repoctl task migrate-slop --apply --json
# For each individually reviewed done, canceled or archived Task:
./scripts/repoctl task migrate-slop T-YYYYMMDDHHMMSSZ --closed --json
./scripts/repoctl task migrate-slop T-YYYYMMDDHHMMSSZ --closed --apply --json
./scripts/repoctl task doctor T-YYYYMMDDHHMMSSZ --json
```

Default apply **never** edits a done/canceled child just because it remains in `docs/tasks/`. One explicit `--closed` Task ID preserves its completion-time bytes in an ignored migration witness and checks the original receipt; receipt/catalogue hashes are not re-sealed. Do not run `--closed --apply` on a Task whose original proof is already mismatched. A proof is not new test/finish evidence. Inspect the precise Execution Log changes, including code fences and authored notes.

## 3. Convert Knowledge v1 only with real provenance

```bash
./scripts/repoctl knowledge migrate --repo-id main --json
# For each verified v1 ID with an existing technical reason and original source:
./scripts/repoctl knowledge migrate --repo-id main --record-id K-... --json
./scripts/repoctl knowledge migrate --repo-id main --record-id K-... --apply --json
# If the original lacks actual reason/source, supply verified input for that one ID:
./scripts/repoctl knowledge migrate --repo-id main --record-id K-... --reason 'Actual observed technical reason' --source docs/specs/example/requirements.md --apply --json
./scripts/repoctl knowledge check --repo-id main --json
./scripts/repoctl knowledge rebuild --repo-id main --json
```

Replace `main` with the repository ID shown by `repo list`. One-record apply prevents partial batch commits. Legacy source bytes are preserved in ignored migration proof. Missing technical reasons must not be invented; unresolved entries remain explicitly reported. Same-claim but different-source/reason records are not equivalent, and referenced old IDs require deliberate citation update.

## 4. Migrate old project documents and references

The current root entrypoint is `docs/PRD.md` and the optional current paths are `docs/architecture/`, `docs/specs/<capability>/`, `docs/adr/`, and `docs/research/`. Old `docs/prd/**` is **not indexed or treated as current product authority**. Copy valuable authored text to the correct current document, review its adoption status, fix references in active Tasks/Knowledge/Workflows, then delete the obsolete path only with the adopter's approval. Avoid empty scaffolding and shadow copies. Do not overwrite adopter-authored `AGENTS.md`, Workflows or `docs/PRD.md` automatically; compare common guidance and reconcile with local policy first.

## 5. Refresh derived evidence and inspect the first task

```bash
./scripts/repoctl check --json
./scripts/repoctl meta check --json
./scripts/repoctl graph build --repo-id main --rebuild --json
./scripts/repoctl graph search 'next implementation and tests' --repo-id main --json
./scripts/repoctl graph workflow --symbol <known-symbol> --repo-id main --json
./scripts/repoctl task resume T-YYYYMMDDHHMMSSZ --json
```

The optional Tree-sitter structural adapter resolves syntax-level relations for Rust, Go, Java/Kotlin, Swift when installed. It does not prove type-dispatched or all cross-file calls. Inspect candidate and confirmed relationships separately and never treat missing tests as zero impact. The old `context` command and `context pack` are **removed**, not legacy aliases; update scripts to `graph search`, `graph query` or `knowledge query` based on their actual data needs.

## Rollback / stopping conditions

Before apply, keep a trusted adopter-specific backup of root docs, original Task/Knowledge files, ignored `.repoctl-state` and the root Git revision. If upgrade fails, restore the root control-plane **and** its matching task/receipt/Knowledge state together from that snapshot; do not restore only the Markdown while keeping later receipts/projections. Product repositories remain separate Git roots and should never be reset as a side-effect. If a per-ID Task/Knowledge conversion reports a conflict, preserve its original backup/witness for audit and stop. After restoration, rebuild only derived Graph/search and Knowledge projections from the restored source. v0.14 uses evidence-index schema 9, so an older schema 8 derived SQLite index is not a supported normal read source; rebuild before treating the new index as current. Release `v0.13.0` must not be reused as the transition target.
