# Knowledge Requirements

Knowledge stores concise reusable decisions, invariants, and failure modes as direct v2 claim/reason/source records. Direct records are authoritative; projections are derived accelerators.

Default query uses a bounded direct-record fallback when a projection is missing, stale, or invalid. Projection damage is a warning; direct-record corruption remains an error. Source digest drift is reported without hiding a record. A missing source may relocate only when one bounded candidate has the recorded identity; ambiguous candidates fail closed.

The only active lifecycle labels are `current` and `superseded`; neither implies human approval. Normal query and derived Graph read validated v2 records only. The explicit, dry-run-first `knowledge migrate` command reports every remaining v1 record and converts one ID at a time with an original-byte witness. Missing reasons or source references are not guessed and conflicting source digests are rejected. Exact duplicates can consolidate only when complete claim/kind/reason/source identity matches and no old references remain. After conversion the v1 file is no longer an ordinary query input; no perpetual runtime v1 equivalence or compatibility status is maintained.

## One-time v1 conversion and finalization

A referenced historical v1 record must never be rewritten into a new assertion or assigned a new completion-time source hash. The first explicit `knowledge migrate --record-id ID --apply` step validates or creates its current v2 successor and records an exact original-byte witness. This is a reversible **staging step**, not a finished cleanup: the v1 JSON still exists in active storage, and `knowledge check` reports it as unfinalized.

After reviewing the specific successor and its citations, `knowledge migrate --record-id ID --finalize` previews the final move and lists any exact authored Markdown record-ID mentions by file and line for manual link repair. Explicit `--finalize --apply` moves unchanged v1 bytes to `docs/archive/knowledge/ID.json`, updates only exact-SHA-256 v2 citations to that historical path, recomputes affected v2 content digests, records before/after evidence and removes the temporary duplicate original witness. Authored Markdown is never rewritten blindly; code examples and historical prose require human interpretation. The active records directory then contains v2 only. Normal query reads v2 directly; no perpetual v1 equivalence engine is required. The one-ID apply rolls back related files when a write fails, including detection of outside-lock concurrent changes. A non-exact source citation, conflicting historical path, unsafe reference, incompatible replacement lineage or transitive current-record citation blocks finalization for explicit review. Current source drift and historical Task evidence are never silently reverified.

## Existing v2 already cites a v1 source (source patch after v0.14.1)

A pre-existing v2 record can establish an explicit source-preserving migration for a historical v1 **without** rewriting the v1 JSON or rebinding changed archived Task source digests. Require an exact v1 SHA-256 citation from v2, same repository/kind/claim, a valid current record digest, a non-empty already-authored reason, and a **unique** current successor. The current scope must not exceed the legacy `applies_to` scope. Any historical paths deliberately retired from current scope are returned as `removed_historical_scope_paths`; their source remains preserved in the unchanged v1 and is never silently relabelled as active. If the current record broadens scope, duplicates a successor, cites changed bytes or fails its contract, this optimization refuses to link and requires separate review. The one-ID staging apply records a digest-verified witness; subsequent explicit finalization redirects exact citations to the byte-identical historical archive and removes the active v1. Remaining `knowledge_source_changed` warnings on existing v2 records are **not suppressed** by conversion.
