# v0.15.2 — guarded rollback of one-time source transitions

This follows v0.15.1. A further source-only audit reproduced incomplete rollbacks that could lose historical evidence or overwrite independent editor changes when a later write failed. The corrections below apply to the explicit migration and upgrade procedures; they do not restore a legacy normal runtime or authorize adopter rollout.

## Source integrity corrections

- **Completion receipt transition:** If an outside writer changes the newly converted receipt, its original v2/v3/v4 bytes remain in the historical receipt archive even if a later proof write fails. Rollback reports the conflict and never treats an incomplete conversion as successful.
- **Closed start-state retirement:** If a state reappears or changes during batch rollback, retain its exact pre-retirement archive. Clean failures still remove their temporary copies, while conflicts stop for owner review.
- **Knowledge v1 staging:** Journal each new witness and v2 output before writing; roll back only byte-identical own writes. A concurrently changed v2 stays intact and reports `knowledge_migration_rollback_incomplete`. Finalization's existing guarded provenance handling remains in place.
- **Package upgrade:** Record expected pre/post file hashes before each mutation. Recheck each managed source and target near replacement or removal, verify backup content, and roll back only writes that still match this upgrade. A conflicting replacement, new file or recreated removed file is preserved, listed under `rollback_conflicts` in `rollback.json`, and reported as `upgrade_rollback_incomplete` with retained backups. Exclusive run-directory creation prevents same-second retries from replacing prior receipts or backups.

Targeted regression tests inject post-write failures, independent edits, and midflight managed-file changes. Successful one-time conversion still preserves historical event gaps rather than inventing dates, transitions or verification. Normal Task, Board, Workflow, Graph and Knowledge interfaces from v0.15.1 are unchanged.

## Transition boundary

Use the current [adopter transition workflow](../workflows/adopter-transition.md) and [upgrade workflow](../workflows/repoctl-upgrade.md) only after owner approval for a specific consumer. Review unresolved historical sources and all incomplete rollback paths individually. Never auto-clean a preserved original or re-run a failed mutation over another editor's work.

No consumer workspace was upgraded, migrated, rebuilt or otherwise changed for this source correction. TabletAuto remained outside the scope. Prior tags and release assets remain immutable.
