# v0.15.1 — independent source acceptance corrections

v0.15.0 was publicly released but **did not meet the full original-Main acceptance criteria**. This corrective version addresses independently reproduced data-modification hazards, Graph benchmark truth conditions, and one-time conversion of genuine older completion receipts. It does not authorize adopter rollout.

## Data-changing operations

- Task generated-log cleanup tracks Markdown code fences across the entire document. A fenced `## Execution Log` example under Notes remains untouched; the real Execution Log is cleaned.
- Knowledge v1 finalization journals expected old/new bytes before writing. Rollback checks actual bytes; if an external v2 edit intervenes, it keeps the edit and exact historical original and reports a concrete incomplete-rollback conflict rather than overwriting that edit.
- Task receipt conversion preserves real v2 receipts that never recorded start events or path transitions as **current v5 with an explicit `historical_transition_evidence.status=not_recorded` marker**. It preserves the byte-identical original and completion Task hash, never invents timing, ownership or changed-path proof, and rejects partially inconsistent evidence.
- A separate, one-ID `task migrate-receipts --relink-knowledge` procedure follows v1 Knowledge finalization. It verifies the exact cited original receipt digest and guarded source-record digests, points current v2 Knowledge to the unchanged archived receipt, and handles interrupted/concurrent writes without erasing an independent editor's update. Normal execution still reads current schemas only.

## Graph acceptance

- The Gakza fixture separates the direct authority test from provider-confirmed secondary Dart library/part dependencies. Verified secondary tests are accepted only with a matching typed source relation; lexical candidates and unrelated tests still count as false positives.
- A genuine Cops-and-Robbers stale-to-current Graph refresh may return `found`; the benchmark still requires checked source and matching current graph evidence. Basic ML API and Kinport required stages, exact-file priority, and partial/precise provenance semantics are retained.

## Current adopter transition boundary

The source-only preview of 30 adopters inspected **3,194** completion receipts: 1,066 already current, 2,115 ready for one-time conversion, and 13 blocked by active old Knowledge citations. The visible ready set includes 1,196 older v2 receipts with genuinely unrecorded transition events; **1,297 source-integrity warnings are separate** and must be reviewed against original Task data, not silently rehashed. The 13 cited receipts require individually reviewed Knowledge v1 stage/finalize, then the one-ID SHA-verified relink before receipt conversion. Hither and HostSpan remain blocked at upgrade planning by missing archived predecessor evidence until their owners resolve real historical data.

See [adopter-transition](../workflows/adopter-transition.md) for release-archive installation, explicit source conversions, current projections, postflight and rollback. Do not reuse v0.15.0 or older rollout instructions. The 30 consumer workspaces remain on v0.12.33; none was upgraded, migrated, rebuilt or otherwise written by this source effort. TabletAuto was excluded.
