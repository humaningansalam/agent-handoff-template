# v0.15.0 — unified source acceptance

This version defines the source contract. It does **not** authorize adopter rollout; the user separately decides when to apply it. Historical v0.13.0–v0.14.3 tags and assets remain untouched.

## Single current contract

- The normal product is Task, live Board and Workflows, with Graph and Knowledge for source-grounded navigation. Task Handoff is four fields of current next action. There is no independent Context Pack, secondary compact Task, Pack export/materialize/benchmark CLI, obsolete CLI aliases or current `docs/prd/**` discovery.
- Internal Graph search/retrieval and field-gate code can reuse bounded source/ranking algorithms; it is not another user-facing Context layer. `docs/PRD.md` is adopter-owned; optional `docs/architecture/`, `docs/specs/<capability>/`, `docs/adr/`, `docs/research/` contain only needed authored material. Examples are illustrative, not requirements of a new adopter.
- The package upgrade manifest preserves adopter-owned PRD, Tasks, Knowledge, Git state and ignored evidence. Legacy package paths are subject to a reviewed one-time removal plan, not runtime compatibility.

## Task and immutable evidence

- New Task logging permits actual multi-line Decision/Reason/Constraint/Result while rejecting confirmed bulk machine output and giant opaque tokens. Chosen records the actual changed source scope rather than validation artifact inventory; no invented detail source reference is emitted.
- Default `task migrate-slop` skips every done/canceled/archived Task even if its Markdown remains under `docs/tasks/`. Explicit `--closed` requires exactly one reviewed ID and intact completion evidence, stores a single original witness, changes the narrow generated Execution Log pattern, and never re-signs historical completion or rewrites code examples. Apply and rollback check exact bytes to preserve concurrent edits.
- v5 is the sole normal completion receipt reader; valid current starts/finishes carry actual event and changed-path transitions. One-time `task migrate-receipts` preserves byte-identical v3/v4 evidence while translating presentation; incomplete v2 events and existing Task digest drift are reported, not fabricated or re-sealed. One-time `task migrate-states` retires only closed v3 start states after verification, preserving original bytes. Archive lookup uses an explicit current Task-ID locator; old receipt-derived implicit archive lookup was removed.
- The current Task source remains the direct readable Markdown. No full/compact parallel copy is introduced.

## Knowledge and Graph

- Normal Knowledge reads use current v2 source records. Individual v1 conversion checks actual claim, reason, source identity and SHA; finalization moves exact original bytes outside active records to `docs/archive/knowledge/`, retargets verified citations and rebuilds projection. Missing real evidence remains a visible blocker. Source-query fallback differentiates missing projections from bad originals.
- Graph exact `--in-file` selection precedes global budgets. Optional Tree-sitter structural adapters supply Rust, Go, Java/Kotlin and Swift relationships without requiring every language tool. Current/stale, compiler/provider-confirmed, source-verified, ambiguous and text-candidate relations remain distinct. Focused fixtures exercise Python `/predict` → manager → API/concurrency tests, Rust `audio_clock`, Dart import/part ownership, and stale-then-refreshed navigation.
- Graph workflow benchmark evaluates every required stage, requires ground truth for callers/tests, penalizes extra false-positive paths, and checks correct first task location. Candidate-only 100% recall is not structural completion.

## One-time rollout, limitations and verification

- Follow [adopter-transition](../workflows/adopter-transition.md) **only after source release verification and explicit user approval**: verify tag/archive/size/SHA; back up owned/ignored data; review package upgrade plan; individually convert Task receipts/states and known slop; stage/finalize evidenced Knowledge v1; relocate valid old docs; rebuild current Graph/Knowledge/history; run checks and postflight. The v0.13.0/v0.14.3 rollout steps are superseded.
- Historical v3 live start states without provable start/dirty evidence, v2 receipts without start/completion transitions, source-digest mismatch, missing archived Task, ambiguous Knowledge equivalence or transitive citation cannot be fixed by inventing data. Report the exact affected record to its owner. Rollback uses preserved original bytes and reviewed upgrade backups, never force-resets product Git.
