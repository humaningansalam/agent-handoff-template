# v0.14.2 — safer historical Knowledge conversion and source-grounded Graph navigation

This is a follow-up source-release patch to v0.14.1, **not a claim that all adopter migrations or compiler-level call/test precision are complete**. It does not modify any of the 30 adopter workspaces or TabletAuto.

## Knowledge: audited one-time historical conversion

- The migration tool detects a **unique, valid current v2 record that already cites the exact v1 source bytes** with a matching SHA-256, claim, kind and repository. `knowledge migrate --record-id ... --apply` records a one-time, hashed original witness and existing-v2 link **without rewriting the v1 or the existing v2**.
- Scope cannot be silently broadened. A narrower current scope reports `removed_historical_scope_paths`; no historical applicability is deleted from the immutable v1. Multiple possible successors, changed cited bytes, invalid v2 records and proof symlinks fail closed. Explicit `--reason` / `--source` overrides are honored.
- On **disposable copies of Bible Simple's four actual v1 JSON files and nine v2 records**, the verified legacy conversion count changed from **4 to 0**, with identical original bytes, preserved existing v2 source hashes, and a valid current v2 projection. One historical path was removed in the current record; it is explicitly reported. **Sixteen existing v2 source-digest drift warnings remain visible**, not falsely marked repaired. No adopter file was written.

## Graph: reliable work-path evidence

- Go: AST-grounded same-package calls across files, with shadowing checks; ordinary `_test.go` files are test sources.
- Rust: exact `mod` file references and uniquely resolved public direct scoped calls; named embedded unit tests are discoverable as **candidates** when no direct TESTS_FILE evidence exists.
- Java/Kotlin: exact declared `package.Type` imports create verified source-file relations; wildcard/static/ambiguous imports do not.
- Dart: relative imports, comment-safe `part` / reciprocal `part of` directives and owner-library→test relationships. Without the Dart analyzer, current source remains navigable but **unconfirmed**; no synthetic provider confirmation is reported.
- Python Flask: source-verified blueprint and factory attribute binding for general implementation classes; dynamic dispatch remains **source**, not invented compiler-confirmed CALLS. Route-related test discovery requires an actual test invocation, excluding unrelated import-only tests.
- Benchmarks distinguish path recall, first source, false positives, confirmed relation precision and independently verified stale→current refresh. `graph workflow-benchmark --verify-refresh` is an **explicit opt-in** that refreshes only the selected workspace's ignored derived Graph cache, verifies stale source changed and fresh snapshot digests differ, and records before/after evidence. A current starting snapshot, absent exact source, missing provider or failed rebuild never counts as proven precision. The default benchmark stays read-only.

## Actual source-only assessment (isolated copies)

- Gakza's exact Dart library/part/test case satisfied required-stage precision, with 100% path recall and zero false-positive paths when its semantic provider was available.
- Cops-and-Robbers stale/empty snapshot passed the refresh acceptance check **only after an actual explicit rebuild and independently verified before/after proof**. A new opt-in CLI workflow can collect this evidence in one transaction; no adopter cache was refreshed here.
- Kinport: 100% named-path recall and confirmed module/dependency location; the cross-crate core unit test is still a **candidate**, not a proven direct test of the daemon drift estimator.
- Basic ML API: 100% named-path recall, zero unrelated tests after filtering, but `current_app` dynamic implementation binding and route-only tests remain source/candidate evidence rather than compiler-confirmed edges.

**Never interpret a candidate-only stage as precise, infer zero tests from stale/incomplete Graph, or treat passed unit tests as adopter postflight.**

## Two adopter archive-authority blockers remain

Read-only upgrade plans for **Hither** and **HostSpan** find dangling archive locators to missing historical Task files. `upgrade plan` now reports the missing path and **claimed** completion-receipt content SHA-256 while refusing to apply; the receipt alone is not an authority to recreate lost Task prose. See [task archive recovery](../workflows/task-archive-recovery.md). Both blockers require exact original bytes from a trusted backup, and neither adopter has been changed.

## Release verification

Compact Graph-search output now adaptively shortens only text excerpts for unusually large queries, preserving all selected source refs, ranked relation evidence and continuations. The 35-question benchmark measured **3,025 → 2,973 estimated max output tokens**, with no change in path recall, precision, visible refs, graph-edge recall or false-positive counts; the release field-gate limit remains 3,000.

Run `uv run --extra structural pytest -q`, `./scripts/repoctl check --json`, `./scripts/repoctl meta check --json`, `./scripts/repoctl field-gate run repoctl-release --full --json`, archive deterministic rebuild/byte comparison, the actual GitHub CI/release job, and read-only upgrade plans. **Do not deploy blindly to all adopters.**
