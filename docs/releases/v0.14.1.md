# v0.14.1 — immutable Knowledge provenance and conservative CALLS

**This patch supersedes v0.14.0 for adoption.** The previous published v0.14.0 passed its test suite, but an independent review found real adopter data could be damaged by `knowledge migrate --apply`, and the optional Tree-sitter structural adapter could falsely label certain unqualified member/local-variable calls as confirmed. **Do not use v0.14.0 for Knowledge conversion.**

## Fixes

- **Knowledge v1 → current v2 is immutable-source-preserving.** The original v1 JSON stays at the same path with identical bytes even when current v2 records cite its SHA-256. Each explicit per-ID migration either associates an exactly equivalent current v2 or saves a separate v2 record. A digest-verified original witness and destination record accompany the one-time conversion; the proof is published last and normal Knowledge query/Graph consumes only current v2 records. Verified, intentionally preserved historical v1 provenance no longer emits recurring migration warnings. Invalid/missing/mismatched proof restores the warning rather than assuming migration succeeded.
- A current v2 `replaces` reference to a preserved v1 ID is valid **only if** the v1/v2 preservation proof is intact; the historical v1 remains excluded from current query heads.
- No conversion invents a missing technical reason, rewrites a changed source digest without explicit reviewed input, changes a completed Task receipt, or applies a batch of uncontrolled v1 rewrites.
- **Graph Tree-sitter CALLS are conservative.** Rust/Go local variables and function parameters shadow same-name functions; an unqualified call is never automatically resolved to an unrelated receiver method or other Java class. Unsupported or ambiguous bindings remain unconfirmed rather than producing a misleading confirmed edge.

## Observed real-source safety checks

- A read-only copy of ResourceShare's two actual legacy v1 records and current v2 citations successfully migrated inside a throwaway workspace: `2 → 0` outstanding v1 migration warnings, no original v1 bytes changed, no existing v2 source-ref hashes changed, and a healthy current v2 projection.
- Bible Simple's four historic v1 records are preserved and **not silently re-hashed**: observed source-digest drift and an unresolved applicability path require review of the actual source and code file. Their conversion remains explicit and is not claimed complete.
- Graph candidate/path recall is not semantic precision. The four adopter snapshot benchmarks remain partial/stale for confirmed required relationships; no adopter workspace was rebuilt or modified.

## Read-only upgrade plan audit across existing adopters

The actual v0.14.1 manifest was checked read-only against **all 30 existing adopter roots** (excluding the template source and TabletAuto): **0** plans would overwrite adopter-owned README, PRD, local tool settings or `.gitignore`. **28/30** have no upgrade-plan conflicts. Two environments must **not** be upgraded automatically: Hither and HostSpan have unresolved references to archived Task files, reported as `archive_locator_migration_conflict` because their referenced predecessor file is missing. This is an explicit stopping condition for owner review, not a successful automatic migration. No adopter or TabletAuto files were changed.

## Validation and rollout boundary

Release tests, workspace checks, release archive integrity, Git tag, and remote CI are separately verified before declaring this patch shipped. The protected one-adopter procedure is in [v0.14 rollout](../workflows/v0.14-rollout.md). **No automatic rollout** to any of the 30 adopters, including TabletAuto, is part of this release.
