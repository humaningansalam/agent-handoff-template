# v0.14.3 — reproducible release archive permissions

This source-release patch carries the v0.14.2 Task, Knowledge, Graph and one-time transition changes forward unchanged. It does not modify any adopter workspace or TabletAuto, and it is not permission to begin the 30-workspace rollout.

## Release archive correction

- The builder now normalizes archived regular-file modes to `0644`, or `0755` when executable. Checkout umask and group-write bits no longer change archive bytes or installed file permissions.
- v0.14.2's published archive and a local developer rebuild contained the same 117 files with identical content, but every mode differed (`0644` vs `0664`; launcher `0755` vs `0775`), so the compressed archives were not byte-identical. The published v0.14.2 asset remains untouched.
- A focused regression builds the same source with two different file-mode sets and requires identical archive bytes and the intended executable mode. The existing deterministic-build and extracted-command checks remain in the release suite.

## Scope and acceptance

All v0.14.2 documented safety boundaries remain: explicit per-ID Task and Knowledge conversion, original receipt/source evidence preservation, Graph source/candidate distinction, and owner review for missing archived authorities in Hither and HostSpan. Kinport cross-crate tests and Basic ML API dynamic dispatch still have honest partial/source evidence rather than invented compiler-confirmed calls. The adopter-wide semantic migration and any product build/deployment remain outside this source release.

Verify the pinned tag, full tests, workspace/meta/field gates, deterministic rebuild, published-asset size/hash and archive-member bytes before authorizing a separately reviewed adopter transition. Rollback restores control-plane files and their matching Task/receipt/Knowledge state together; never reset product repositories as a side effect.
